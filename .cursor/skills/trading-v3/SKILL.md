# 交易 V3

## 职责边界

把仓库根目录的 `V3.txt` 视为唯一策略、授权、风控和下单边界来源。本 skill 只负责把 Codex 的操作流程适配到 V3：读取规则、读取真实账户和行情、自由分析、脚本/联网/后端研究、执行前核验、通过授权交易通道执行动作、动作后复核、输出审计摘要。

不要复制或改写 `V3.txt` 的交易规则。每次 V3 轮次开始时都重新读取 `V3.txt`；如果缺失、不可读或规则互相矛盾，停止真实执行并报告。

不要套用 V2 的截面、CTA、Top 5、固定周期、固定指标、固定候选表或固定报告字段。V3 的目标是盈利，允许 AI 自由决定看什么、怎么分析、写什么脚本、连什么后端、查什么资料、是否下单、下什么单、如何管理已有仓位；skill 只保留数据真实性、密钥保护、执行复核和审计纪律。

## 启动检查

1. 读取 `AGENTS.md`，确认项目本地 skill 约定。
2. 读取 `V3.txt`，把它作为当前轮唯一策略文件。
3. 确认 `ccxt-mcp` 和其他已配置交易后端是否可用。真实账户动作优先走 `ccxt-mcp`；如果用户另行配置并授权其他交易后端，也可以使用。脚本、REST、网页、SDK、数据库和临时后端可以用于研究、行情、筛选、计算、告警和风控辅助。
4. 生成本轮 `cycle_id`。如果 `audit-system` 可用，写入本地审计事件；如果不可用，记录 `auditUnavailable`，但这不替代任何风控检查。
5. 调用 `ccxt_get_config`，确认 exchange、defaultType、凭据、代理、`CCXT_ENABLE_TRADING` 和 `CCXT_DRY_RUN`。

## 每轮执行流程

1. 读取账户、余额、positions、合约普通未成交委托、条件单和保护单。持仓事实只能来自 positions 或账户 position 字段，不能由止损、止盈、触发单或 reduce-only 单反推。
2. 处理已有仓位和订单：识别裸露风险、孤立保护单、方向冲突、数量不匹配和保护缺失。V3 允许自由处理，但账户或保护状态不清楚时不得新增真实风险。
3. 按 V3 自由选择本轮需要的行情、背景数据和研究工具。可以写脚本、运行扫描器、建立临时数据库、启动临时后端、联网查询网页/新闻/公告/API/GitHub/链上或衍生品数据，再对关注对象补充 K 线、盘口、资金费率、mark/open interest 或其他必要数据。
4. 自由分析市场，不要为了填模板而制造候选、排名、置信度或指标解释。可以直接决定等待、开仓、平仓、减仓、加仓、撤单、改单、反向、启动额外研究脚本或只复核。
5. 每个准备执行的真实账户动作都必须先核验 `V3.txt` 的边界：市场范围、杠杆、保证金、名义金额、最大可预估亏损、持仓数量、同 symbol 净方向、数据来源、退出/保护方案、密钥不外泄和动作后复核路径。V3 允许 AI 自主突破默认风险参考线，但必须说明原因和风险。
6. 如果 `CCXT_ENABLE_TRADING=true` 且 `CCXT_DRY_RUN=false`，并且 V3 边界全部满足，可以自主通过 `ccxt-mcp` 提交真实订单，不需要再次请求人工确认。否则只能 dry-run 或输出计划。
7. 执行后必须重新读取账户、positions、合约普通未成交委托、条件单和保护单。若保护或退出机制未确认，优先撤销未成交单、减仓或平仓，并再次复核。
8. 输出最终总结。总结不需要 V2 模板，但必须足够让人复核本轮数据、判断、动作、订单响应、保护状态、账户风险和审计链路。

## 工具和联网权限

- 允许为盈利目标写脚本、运行脚本、创建临时扫描器、临时数据库、临时后端、缓存、仪表盘和告警。
- 允许使用 web search、浏览器、新闻、公告、项目官网、交易所页面、GitHub、外部 MCP、REST API、SDK、链上数据、衍生品数据、宏观数据和舆情数据。
- 允许脚本和后端参与排序、筛选、回测、风控测算、仓位测算、告警和报告生成。最终真实账户动作必须能解释、能复核、能审计。
- 账户、持仓、订单、保护状态和真实执行优先通过 `ccxt-mcp`；如存在用户明确配置并授权的其他交易后端，也可以使用。
- 不得把 API key、secret、token、`.env` 内容或账户隐私写入日志、URL、网页请求、第三方服务或输出摘要。
- `ccxt_call` 可以用于明确需要的只读或交易方法；交易类调用必须先通过 V3 执行边界。
- 不要创建脱离当前会话控制且无法审计的持久 runner。若需要长时间后台进程，必须记录用途、命令、日志位置、停止方式和它是否可能触发真实账户动作。

## 最终总结最低内容

用中文输出，至少包含：

1. `cycle_id`、使用的策略文件路径和审计状态。
2. exchange、`CCXT_ENABLE_TRADING`、`CCXT_DRY_RUN`、代理/凭据可用性摘要。
3. 账户权益、可用余额、保证金占用、未实现盈亏、持仓数、未成交委托和保护状态。
4. 本轮自由分析：实际读取了哪些数据，为什么足够行动或为什么不足。
5. 脚本、后端和联网研究：运行了什么、查询了什么来源、关键时间戳、结论如何影响决策。
6. 本轮决策：等待、dry-run、下单、撤单、改单、减仓、平仓、反向或只管理已有仓位。
7. 每个动作的 symbol、方向、订单类型、价格/触发价、数量、杠杆、保证金、名义金额、最大可预估亏损和退出/保护方案。
8. 执行结果：订单 ID、成交状态、失败原因、补救动作。
9. 动作后复核：最终持仓、未成交委托、保护单、账户风险、仍未解决的问题和下一轮重点。

## 禁止事项

- 不要读取 `V2.txt` 作为 V3 决策依据，除非用户明确要求比较 V2/V3。
- 不要把 V2 的方法论、字段或模板补回 V3。
- 不要在账户、订单、持仓、保护或交易开关不清楚时提交真实新增风险。
- 不要编造行情、网页资料、脚本输出、成交、订单 ID、审计 hash 或账户字段。
- 不要泄露密钥或把密钥发送给外部服务。
- 不要把审计系统当作交易系统；审计系统只能记录和展示本地事件。
